# Как поднять сайт ker-ai.online

Инструкция для человека, который не занимается серверами каждый день.
Читайте сверху вниз, ничего не пропуская. Каждый шаг устроен одинаково:

- **Зачем** — что мы вообще делаем и почему.
- **Делайте так** — команды, которые надо скопировать.
- **Должно получиться** — что появится на экране, если всё хорошо.
- **Если не получилось** — что делать прямо здесь, не листая в конец.

Всего 8 шагов. Активной работы примерно час, плюс ожидание в шаге 1
(от 5 минут до нескольких часов, зависит не от вас).

---

## Сначала — короткий словарик

Пять слов, которые дальше встретятся. Если они знакомы — пропускайте.

**Домен** — `ker-ai.online`, адрес, который люди набирают в браузере.

**DNS** — телефонная книга интернета. Она связывает домен с числовым
адресом сервера (IP). Без неё браузер не знает, куда стучаться.

**IP-адрес** — номер вашего VPS в интернете, вроде `123.45.67.89`.

**Сертификат** — файл, который доказывает браузеру, что сайт настоящий.
Без него вместо замочка будет красное предупреждение. Мы получим его
бесплатно у Let's Encrypt.

**HTTPS** — защищённая версия адреса (`https://` вместо `http://`).
Работает как раз благодаря сертификату.

**Ветка (branch)** — версия кода в git. У нас их две: `main` и рабочая
`claude/jarvis-repository-9gp7wj`. Всё новое лежит в рабочей.

> ⚠️ **Важно про ветку.** Этот файл и весь код сайта есть **только** в
> ветке `claude/jarvis-repository-9gp7wj`. В `main` их нет. GitHub
> открывает `main` по умолчанию — если файлов «не видно», причина почти
> всегда в этом. На сервере ветку переключим в шаге 2.

---

## Что понадобится под рукой

Прежде чем начинать, приготовьте:

1. **Доступ в панель, где куплен домен** — логин и пароль от регистратора.
2. **Доступ к серверу по SSH** — вы уже умеете, вы туда заходили.
3. **Ваша почта** — на неё Let's Encrypt пришлёт предупреждение, если
   сертификат вдруг перестанет обновляться.

Больше ничего. Платить ни за что не нужно, сертификат бесплатный.

## Что получится в конце

| Адрес | Что там будет |
|---|---|
| `https://ker-ai.online` | Официальный сайт |
| `https://ker-ai.online/api/…` | API — сюда ходят exe, бот, Raspberry Pi |
| `https://dashboard.ker-ai.online` | Веб-кабинет (пока заглушка «скоро») |
| `https://www.ker-ai.online` | Просто перебросит на основной адрес |

# Шаг 1 из 8. Прописать домен в DNS

### Зачем

Сейчас домен `ker-ai.online` куплен, но никуда не ведёт. Надо сказать
интернету: «этот адрес — вот тот сервер». Это делается один раз.

### Сначала узнайте IP сервера

Зайдите на сервер по SSH и выполните:

```bash
curl -4 ifconfig.me
```

**Должно получиться:** одна строчка вида `123.45.67.89`. Это и есть IP
вашего сервера. Запишите его, он нужен на следующем экране.

### Теперь в панели регистратора

Откройте сайт, где покупали домен, найдите раздел «DNS», «DNS-записи»
или «Управление зоной». Добавьте **три записи типа A**. Везде в поле
значения — тот самый IP, который вы только что узнали.

| Тип | Имя (host) | Значение |
|---|---|---|
| A | `@` | IP вашего сервера |
| A | `www` | IP вашего сервера |
| A | `dashboard` | IP вашего сервера |

> Символ `@` означает «сам домен, без приставок». В некоторых панелях
> вместо `@` надо оставить поле пустым или написать сам домен целиком —
> это одно и то же, смотрите по подсказкам вашей панели.

**Все три записи обязательны.** Сертификат в шаге 5 выпускается сразу на
три имени. Если хотя бы одно не работает — Let's Encrypt откажет во всём
запросе, и вы получите непонятную ошибку. Проще сделать сразу три.

### Теперь ждём

Новые записи расходятся по интернету не мгновенно: от 5 минут до
нескольких часов. Это нормально и от вас не зависит.

Проверять так — на сервере выполните три команды подряд:

```bash
dig +short ker-ai.online
dig +short www.ker-ai.online
dig +short dashboard.ker-ai.online
```

**Должно получиться:** каждая команда печатает IP вашего сервера. Три
команды — три одинаковых IP.

**Если не получилось:** команда molчит или печатает что-то другое —
записи ещё не разошлись. Подождите 15 минут и повторите. Если через
пару часов всё так же пусто — вернитесь в панель регистратора и
проверьте, что записи сохранились (иногда надо нажать отдельную кнопку
«Применить»).

> 🛑 **Не идите дальше шага 4, пока все три команды не покажут ваш IP.**
> Сертификат без работающего DNS не выпустится, и вы просто потратите
> попытки.

# Шаг 2 из 8. Забрать свежий код на сервер

### Зачем

Код сайта уже написан и лежит на GitHub, но на вашем сервере его пока
нет. Забираем.

### Делайте так

```bash
cd /root/K.E.R-server

git fetch origin claude/jarvis-repository-9gp7wj
git checkout claude/jarvis-repository-9gp7wj
git pull
```

Три команды: скачать ветку, переключиться на неё, подтянуть последнее.

> В прошлый раз именно здесь всё встало: `git pull` отвечал «Already up
> to date», потому что сервер сидел на ветке `main`, где нового кода нет.
> Команда `git checkout` выше как раз это и чинит.

Проверьте, что нужные файлы приехали:

```bash
ls docker-compose.prod.yml web/site/package.json
```

**Должно получиться:** две строчки с именами этих файлов, без слова
`No such file`.

**Если не получилось:** видите `No such file or directory` — значит
`git checkout` не сработал. Посмотрите, на какой вы ветке:

```bash
git branch --show-current
```

Должно напечатать `claude/jarvis-repository-9gp7wj`. Если напечатало
`main` — повторите три команды выше и посмотрите, не ругается ли
`git checkout` на несохранённые изменения.

# Шаг 3 из 8. Вписать настройки в файл `.env`

### Зачем

`.env` — файл с настройками. Там уже лежат ваши ключи от ИИ и токен
бота. Надо дописать пять строк про домен.

### Делайте так

Откройте файл редактором:

```bash
cd /root/K.E.R-server
nano .env
```

> Если ругается, что файла нет — создайте его из образца:
> `cp .env.example .env`, потом снова `nano .env`.

Найдите эти строки и приведите к такому виду. Если строки нет —
допишите её в конец файла.

```env
DOMAIN=ker-ai.online
LETSENCRYPT_EMAIL=ваша@почта.ру

# Пока проверяете — оставьте 1. Что это значит, объясню в шаге 5.
CERTBOT_STAGING=1

# Чтобы вход работал и на сайте, и на поддомене.
# Точка в начале обязательна, это не опечатка.
SESSION_COOKIE_DOMAIN=.ker-ai.online
SESSION_COOKIE_SECURE=true
```

Замените `ваша@почта.ру` на свою настоящую почту. Остальное копируйте
как есть.

Сохранить в nano: `Ctrl+O`, потом `Enter`, потом `Ctrl+X` для выхода.

**Должно получиться:** вернулись в обычную командную строку.

**Если не получилось:** случайно всё испортили — выйдите без сохранения
(`Ctrl+X`, затем `N`) и начните шаг заново.

> Остальные строки в `.env` не трогайте. Там ключи, которые уже работают.

# Шаг 4 из 8. Собрать сайт

### Зачем

Сайт написан на исходном коде, который браузер не понимает. Его надо
один раз «собрать» в обычные файлы — картинки, стили, HTML. Дальше
сервер просто отдаёт готовое.

### Сначала проверьте Node.js

Это программа, которая делает сборку. Нужна версия 20 или новее.

```bash
node --version
```

**Должно получиться:** что-то вроде `v22.11.0` — цифра после `v` не
меньше 20.

**Если не получилось** — команда не найдена или версия 18 и ниже:

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt-get install -y nodejs
```

Потом проверьте `node --version` ещё раз.

### Теперь сборка

```bash
cd /root/K.E.R-server
make web-install
make web-build
```

Первая команда скачивает вспомогательные библиотеки — нужна только
первый раз и после больших обновлений. Идёт пару минут, печатает много
строк, это нормально.

Вторая собирает и сайт, и веб-кабинет.

Проверьте результат:

```bash
ls web/site/dist/index.html web/dashboard/dist/index.html
```

**Должно получиться:** две строчки с этими путями.

**Если не получилось:** `No such file` — сборка не прошла. Прокрутите
вывод `make web-build` вверх и поищите строку со словом `error`. Чаще
всего причина — старый Node.js, вернитесь на полшага назад.

> 🛑 **Собрать надо обязательно до шага 6.** Сервер подключает эти две
> папки как есть. Если их нет в момент запуска, Docker создаст вместо
> них пустые, и сайт ответит ошибкой 403 — а причина будет неочевидной.

# Шаг 5 из 8. Получить сертификат и включить HTTPS

### Зачем

Чтобы в браузере был замочек, а адрес начинался с `https://`. Всё
делает один готовый скрипт: создаёт временный сертификат, поднимает
веб-сервер, запрашивает настоящий сертификат у Let's Encrypt на все три
имени и перезагружается.

### Делайте так

```bash
cd /root/K.E.R-server
./deploy/nginx/init-letsencrypt.sh
```

Скрипт рассказывает, что делает, шагами `1/5`, `2/5` и так далее.

**Должно получиться:** в конце строка
`Done. Certificate for ker-ai.online is live.`

**Если не получилось** и в тексте мелькает слово `challenge` — значит
одно из трёх имён не резолвится. Вернитесь в шаг 1 и прогоните три
команды `dig`. Скорее всего, забыта запись `dashboard`.

### Про `CERTBOT_STAGING=1` — прочитайте, это важно

Сейчас вы получили **тестовый** сертификат. Браузер на него будет
ругаться: «подключение не защищено». Это нормально и сделано нарочно.

Причина: у Let's Encrypt жёсткий лимит — **5 настоящих сертификатов в
неделю на домен**. Если сразу гнаться за настоящим и что-то настроить
неправильно, можно сжечь все попытки и ждать неделю. Поэтому сначала
тестовый: лимита у него нет.

**Когда всё заработает** (дойдёте до конца шага 7 и увидите сайт):

1. Откройте `.env`: `nano .env`
2. Поменяйте `CERTBOT_STAGING=1` на `CERTBOT_STAGING=0`
3. Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`)
4. Запустите скрипт ещё раз: `./deploy/nginx/init-letsencrypt.sh`

Придёт настоящий сертификат, предупреждение исчезнет, появится замочек.

### Продление

Делать ничего не надо. В системе есть отдельный контейнер `certbot`,
который сам обновляет сертификат до истечения срока. Раз в 90 дней,
автоматически.

# Шаг 6 из 8. Запустить всё

### Зачем

Код есть, сайт собран, сертификат получен. Осталось включить.

### Делайте так

```bash
cd /root/K.E.R-server
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Команда длинная, скопируйте целиком одной строкой. Первый запуск идёт
несколько минут и печатает много текста.

Подождите минуту и проверьте:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
```

**Должно получиться:** таблица, где у каждой строки в колонке состояния
написано `Up`. У строки `api` — ещё и `healthy`.

**Если не получилось** и что-то в состоянии `Exit` или `Restarting` —
посмотрите, на что жалуется именно этот контейнер. Например, для `api`:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs api --tail 100
```

Последние строки обычно прямо называют причину.

# Шаг 7 из 8. Проверить, что работает

### Зачем

Убедиться, что все четыре адреса отвечают, прежде чем переводить на них
приложение.

### Делайте так

По одной команде, сверяя с ожидаемым.

```bash
# 1. Сайт отдаётся
curl -skI https://ker-ai.online | head -1
```
Ждём: `HTTP/2 200`

```bash
# 2. API живёт
curl -sk https://ker-ai.online/api/
```
Ждём: строку, начинающуюся с `{"name":"KER"` и содержащую `"status":"online"`

```bash
# 3. www перебрасывает на основной адрес
curl -skI https://www.ker-ai.online | head -1
```
Ждём: `HTTP/2 301`

```bash
# 4. Поддомен кабинета отвечает
curl -skI https://dashboard.ker-ai.online | head -1
```
Ждём: `HTTP/2 200`

> Буква `k` в `-skI` velит curl не придираться к сертификату. Пока у вас
> тестовый сертификат — она нужна. После перехода на настоящий
> (`CERTBOT_STAGING=0`) можно проверить ещё раз без неё: `-sI`.

### И главное — откройте в браузере

Наберите `https://ker-ai.online`. Должен открыться тёмный сайт с
зелёным акцентом.

### Если не получилось

**Браузер пишет «не удаётся установить соединение»** — сайт не запущен
или DNS не доехал. Проверьте шаг 1 (три команды `dig`) и посмотрите
веб-сервер:
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs nginx --tail 50
```

**Открывается пустая белая страница или ошибка 403** — нет собранных
файлов. Вернитесь в шаг 4, сделайте `make web-build`, потом перезапустите
веб-сервер:
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --force-recreate nginx
```

**`/api/` отвечает `502 Bad Gateway`** — не поднялся контейнер `api`:
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs api --tail 100
```

**Вход по коду из Telegram даёт ошибку** — настоящая причина всегда в
логах, а не в тексте на экране:
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs api --tail 100
```
И учтите: код одноразовый. Если он уже был введён — даже неудачно —
нужен новый из бота.

**Хочется просто всё перезапустить:**
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml restart
```

# Шаг 8 из 8. Перевести приложение на новый адрес

### Зачем

Ваш exe до сих пор ходит на старый адрес с портом. Пора на красивый.

### Делайте так

В настройках desktop-приложения вместо старого `http://IP:8000`
впишите:

```
https://ker-ai.online/api
```

Для Raspberry Pi или скрипта-агента то же самое через переменные:

```bash
export KER_SERVER_URL=https://ker-ai.online/api
export KER_API_KEY=ваш-ключ
python -m jarvis.desktop.agent
```

> Старый адрес `http://IP:8000` продолжает работать — порт никто не
> закрывал. Можно переводить устройства по одному, не торопясь, и в
> любой момент вернуться назад.

## Как обновлять сайт потом

Когда я внесу изменения в сайт:

```bash
cd /root/K.E.R-server
git pull
make deploy-web
```

Если менялся код бота или API:

```bash
cd /root/K.E.R-server
git pull
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

## Что пока не доделано — честно

1. **Два файла бэкенда ещё не в этой ветке** — `jarvis/api/app.py` и
   `jarvis/licensing/service.py`. Из-за этого нет отдельной проверки
   `/api/status` (поэтому в шаге 7 мы стучимся в `/api/`), нет разделов
   «устройства» и «автоматизации» в веб-кабинете. На работу сайта, бота,
   exe и входа по коду это не влияет — главное исправление ошибки 500
   уже в ветке.

2. **Шрифт Inter не приложен.** Сайт покажется системным шрифтом. На
   Windows это Segoe UI, выглядит достойно. Захотите настоящий Inter —
   положите `InterVariable.woff2` в `web/site/public/fonts/`.

3. **Конфиг веб-сервера не проверен командой `nginx -t`** — в моём
   окружении не было запущенного Docker. Синтаксис я вычитал глазами, но
   первый запуск стоит делать, поглядывая в `logs nginx`.

4. **Веб-кабинет — заглушка «скоро».** Бэкенд под него готов, интерфейс
   следующая задача.

5. **Цены в тарифах** взяты из кода: Plus = 2500 Telegram Stars,
   Pro = 8000. В присланном вами макете было 299 ₽ и 899 ₽ — это
   отличается примерно в 15 раз. Сайт сейчас показывает то, что реально
   спишет бот. Если правильные цифры из макета — скажите, поменяю в двух
   местах: `web/site/src/config/plans.ts` и `jarvis/billing/plans.py`.

Напишите мне, на каком шаге и что именно вывела команда — вместе с
текстом ошибки. По тексту почти всегда видно причину.
